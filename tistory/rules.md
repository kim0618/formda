# 폼다 문서 노트(티스토리) 원고 규칙 v1

작성 2026-11-20. 블로그 주소 https://formda.tistory.com
제이퍼 티스토리 규칙(`~/jptcalc/tistory/rules.md`)을 옮겨 온 것이다. 계산기 숫자 검증은 **법 조항·서식 칸·도구 동작 검증**으로 바꿨고, 나머지(목적, 발행 운영, 품질 §11)는 제이퍼에서 실제로 겪은 일을 그대로 가져왔다. 네이버 블로그 규칙(`~/formda/blog/quality.md`)과는 별개 문서다.

## 0. 목적

네이버 블로그(폼다 매일 발행): 네이버 검색 + 애드포스트 조회수.
티스토리: **구글 색인 → 애드센스 승인**, 그리고 formda.kr이 구글에서 발견될 외부 경로를 만드는 것(11/18 전수 검사: formda.kr URL의 발견 경로는 sitemap뿐이고 외부 링크 0).
독자는 구글(일부 다음)에서 검색해 들어온 사람이다. 네이버 전용 규칙(제목 앞 12자, 분량 고정, 캡처 여러 장, 댓글 유도)은 쓰지 않는다.

## 1. 발행

1. **주 5편, 월~금 08:00 예약**(11/20 사용자 확정). 첫 글 12/1(월).
2. 요일별 카테고리 고정: 월 직장·퇴사 서류 / 화 취업·알바 / 수 돈·계약 / 목 사업 거래 / 금 생활 도구. 같은 카테고리 연속 금지.
3. 예약 등록은 Claude가 윈도우 크롬 자동화로 한다(`/formda-tistory-publish`). 확인은 사용자.
4. 광고(수익 메뉴) 연결 금지. 애드센스 신청 기준은 공개 글 20편 + 구글 색인 15편 + 소개 페이지(11/20 완료) + 개인정보처리방침 페이지(미완).

## 2. 주제 고르기와 중복 판정

**같은 주제·검색어는 피할 필요 없다. 피할 것은 "같은 글"이다**(제이퍼 11/19 결정과 같은 이유: formda.kr·네이버 블로그·티스토리는 구글에게 서로 다른 사이트이고, formda.kr은 구글 색인이 사실상 없다).
1. 사이트 가이드(`~/formda/data/guides.js`)·도구 페이지 본문·네이버 블로그(`~/formda/blog/queue.md`의 배정표와 발행분 대장)와 같은 검색어 허용. 단 각도(질문), 예시 인물·금액·상황, 표 구성, 문장을 새로 잡는다. 기존 글을 열어 놓고 고쳐 쓰지 않는다.
2. 네이버 큐와 **같은 날 같은 도구**는 피한다. 같은 검색어면 네이버 글이 쓴 각도(소제목 대장)를 피한다.
3. **티스토리 자기 글끼리**는 축이 겹치지 않게 한다(알바 이력서 t2·t17처럼 같은 도구 두 번이면 질문 자체가 달라야 한다).

우선 고를 주제
0. **피할 주제**: 노무·법 제도 설명만 하는 글(실업급여 조건, 해고 절차 등)은 고용노동부·노무사·법률 사이트와 AI 요약이 구글 상위를 잡는다. 서식 칸을 채우는 문제로 바꿀 수 없으면 쓰지 않는다.
1. **"이 칸에 뭘 쓰나" + 채운 예시**: 사람들이 실제로 막히는 칸(퇴직일, 근무 가능 시간, 이자, 공급가액, 동호수)과 상황별로 채운 예시 비교. 이게 다른 양식 사이트(빈 hwp 파일 배포)에 없는 정보다.
2. **금액별·상황별 표**: 차용증 금액별 이자 상한, 견적서 금액별 부가세, 미수금 금액별 지연손해금처럼 계산이 들어가는 칸.
3. 생활 도구(PDF·영문 주소·이름·글자수·QR)는 검색량이 서류보다 10~100배 크다. 단 헤드텀 첫 화면은 네이버 자체 도구·대형 사이트일 가능성이 커서, 구체적 사용 사례(아파트 동호수, 휴대폰에서 합치기, 성씨별 표기)로만 쓴다.
4. 근거 숫자는 큐에 적는다(키워드사운드 12개월 평균·최고월, 네이버 블로그 조회수). 근거 없는 칸은 채우지 않는다.

## 3. 제목

1. 검색어를 앞에, 자연스러운 문장으로. 공백 포함 42자 이하. **첫 쉼표 앞 = 검색어**(대표이미지에 크게), 뒤 = 결론(노란 줄).
2. 결론(어느 칸에 무엇을, 얼마)을 제목에 써도 된다. 제목과 본문이 일치해야 한다.
3. 낚시형 반전, 과장, "무료 다운로드" 같은 파일 배포 약속 금지(이 블로그는 파일을 배포하지 않는다. 폼다 도구로 만든다).
4. 연도는 그해 기준이 실제로 적용되는 글에만(최저임금, 법 개정 시행일 등).

## 4. 본문

1. **분량 목표 없음.** 질문에 답하는 데 필요한 만큼(대체로 1,500~3,500자). 늘리려고 쓰는 문단 금지.
2. 첫 3~4줄 안에 질문의 답을 준다(어느 칸에 무엇을 쓰는지, 얼마인지).
3. 구조: 소제목(H2) 3~6개, 필요하면 표 0~3개.
4. **"직접 채워 본 예시"가 핵심.** 폼다 도구에 실제로 넣은 사례 2~4개(상황이 다른 사람들). 예시 인물·회사는 가상임이 드러나게 평범한 이름으로, 실존 회사명 금지.
5. 기준 표기: 글 끝 회색 한 줄 "기준: 민법 제○조·근로기준법 제○조 · 확인일 2026-11-○○". 맨 위에 두면 목록 요약이 그 줄로 시작한다.
6. 문체: 해요체. em dash, 마크다운 볼드 기호 금지. 이전 글을 번호·날짜로 언급 금지. 도구 화면 묘사(색·버튼 위치) 금지(입력 순서 안내는 괜찮다).
7. **글쓴이 한 단락**(면책 줄 바로 위): "글쓴이 폼다" + 그 글에서 한 작업 한 가지(예: 세 가지 상황으로 사직서를 직접 채워 봤다) + `https://formda.tistory.com/page/about` 링크. 고정 첫 문장 금지, 글마다 다르게.
8. **간격**: 오디세이 스킨은 문단 간격 0, 인라인 margin 무시. 문단·표·목록 뒤(다음이 문단일 때) `<p data-ke-size="size16">&nbsp;</p>` 스페이서. 표는 4칸 이하, 숫자 칸 nowrap(`fix_tables.py`), 휴대폰 340px 확인(`mobile_check.mjs`).
9. **법 효력 단정 금지**: "이걸 쓰면 무효", "법적 효력이 있다", "소송에서 이긴다", "징계를 피한다" 같은 문장은 조문·판례 원문을 확인했을 때만, 그것도 원문 범위 안에서. 확인 못 하면 "~로 안내돼 있어요" 수준으로 낮추거나 뺀다. 끝에 "개별 사안은 전문가 확인" 면책 줄.

## 5. 링크

1. 폼다 도구 링크 글당 1~2개. 예시 직후 1개 + 끝 1개(또는 하나만).
2. 주소는 `https://formda.kr/tools/<slug>`(**www 없이, 끝 슬래시 없이**. www는 301, 끝 슬래시는 308로 넘어간다, 11/20 확인). UTM: `?utm_source=tistory&utm_medium=blog&utm_campaign=t{N}`.
3. 프리필 링크 금지.
4. 관련 티스토리 글 내부 링크는 글이 쌓인 뒤 1개까지.
5. 제이퍼·부모혜택·러브타로 링크 넣지 않는다.

## 6. 이미지

1. **도구 캡처 1장 필수**(직접 채워 봤다는 증거). 본문 예시 하나를 실제 formda.kr 도구에 넣은 입력+미리보기 화면. 헤드리스로 찍는다: `cap.mjs` + `caps/setup/tNNN.js`(스킬 6단계). 유료 저장 안내 카드는 스크립트가 숨긴다.
   - **도구의 예시 문구가 남지 않게** 본문에 쓰인 칸은 전부 setup.js에서 채운다(11/20 시험: 사직서 사유 칸에 도구 기본 예시 "2018년 3월 1일 입사…경영지원팀"이 남아 입력값과 어긋났다). cap.mjs가 찍는 "미리보기 글자"를 끝까지 읽어 본문 예시와 같은지 본다.
   - 문서만 크게 보여야 하면 `MODE=preview`.
2. 캡처 아래 회색 한 줄 설명. alt에 내용을 쓴다("퇴직 희망일 2026-12-31로 채운 사직서 미리보기").
3. **대표이미지**: 카테고리마다 배경색·아이콘 고정, 글자는 그 글 제목만. `python3 make_thumb.py thumbs/tNNN.jpg "카테고리" "제목"`. 직장·퇴사 서류=남색·문서, 취업·알바=청록·명함, 돈·계약=갈색·₩, 사업 거래=보라·계산기, 생활 도구=초록·격자(11/20 PDF에서 변경: QR·영문 변환 글에 PDF 그림이 어긋남). 같은 이미지를 본문 맨 위(`<p>[[TOPIMG]]</p>`)에도 넣는다. 글 상단은 스킨 CSS로 흰 바탕(`skin/white-header.css`, 11/20 적용).
4. 업로드는 `/formda-tistory-publish`가 크롬 자동화로 한다.

## 7. 사실 검증 (계산기 대신 이것)

1. **법 조항**: `LD_LIBRARY_PATH=$HOME/.local/emulib node ~/jptcalc/scripts/law-render.mjs <법령명> <출력경로>`로 원문 조문을 확인한다(민법, 근로기준법, 이자제한법, 부가가치세법, 상법, 소득세법 등). 조문 번호·숫자(연 20%, 3년, 30일 등)는 원문 확인 없이 쓰지 않는다.
2. **정부 서식·고시**: 고용노동부 표준근로계약서, 국세청 서식, 외교부 여권 로마자 표기 등은 기관 원문을 찾았을 때만 "공식"이라고 쓴다. fetch가 막히면 헤드리스 렌더로 연다.
3. **도구 동작**: 도구가 무엇을 해 주는지(자동 계산, 한글 금액 표기, 파일명, 칸 이름)는 `~/formda/engine/` 구현이 정본이다. registry.js 설명·FAQ는 2차 출처라 틀릴 수 있다(9/4 PDF 파일명 사고). 칸 이름은 실제 페이지(`run.mjs`)에서 확인한다.
4. **계산이 들어간 숫자**(부가세, 이자, 지연손해금, 날짜·기한, 합계): python3 또는 `run.mjs`로 다시 뽑는다. 머리로 더하지 않는다. 표의 숫자를 도구 미리보기 숫자와 대조한다.
5. 통계·"대부분" 같은 일반화는 출처가 있을 때만.

## 8~9. 전달·발행 후

1. 발행 후 `ledger.tsv`에 날짜·번호·글번호·카테고리·제목·도구·축·도입·구성 기록.
2. 발행 2주 뒤 GSC API로 색인 확인(서비스 계정이 formda.tistory.com 속성에 제한 권한, 11/20 확인). 4주 뒤에도 0이면 원인 진단.
3. 법 개정으로 기준이 바뀔 때만 고치고 날짜를 갱신한다.

## 10. 자동 발행 운영 규칙 (제이퍼 §10과 같음)

### 10-1. 언제 하나
1. 사용자가 시키면 **다음 주 월~금 5편을 한 번에** 쓰고(`/formda-tistory`), 재검증(`/formda-tistory-verify`), 예약(`/formda-tistory-publish`).
2. 예약은 발행 시각보다 최소 하루 앞서.

### 10-2. Claude가 해도 되는 것 / 안 되는 것
해도 됨: 새 글 예약 발행(08:00, 공개), 발행 전인 내가 건 예약 글의 본문·이미지 수정, 이미지 업로드.
안 됨(사용자가 그때 시킬 때만): 즉시 발행(예약이 안 걸리면 임시저장으로 멈춤), 발행된 글 수정·삭제, 블로그 설정·스킨·메뉴·카테고리·플러그인 변경, 수익 메뉴, 댓글·공감.

### 10-3. 크롬 자동화
- 작업 폴더는 제이퍼와 분리: `Downloads\claude-chrome\formda-batch`, `formda-verify`, `formda-shots`.
- 프롬프트는 영어, 한글 데이터는 파일로 Read. 끝에 자기가 연 탭을 모두 닫는다. 로그인 풀리면 멈추고 사용자에게 요청.
- 새 페이지·글에서 setContent 뒤 에디터가 변경을 못 알아채 빈 본문으로 저장된 적이 있다(11/20 소개 페이지). 저장 전 본문이 채워졌는지 확인시킨다.

### 10-4. 보고
예약은 Claude, 확인은 사용자. 끝나면 날짜별 제목·주소·확인할 점을 한 번에. 사용자가 편집 화면에서 직접 저장하면 예약이 풀릴 수 있으니 고칠 곳은 말로 받는다.

### 10-5. 발행 전 점검
실패는 숨기지 않고 보고. 이미지 "검토중" 자리표시는 자동 해제되므로 확인·보고하지 않는다(11/23 사용자).

## 11. 글 품질: AI 티 금지·틀 반복 금지 (최우선, 제이퍼 11/19~20 그대로)

목표는 "검색해서 들어온 사람이 양식 사이트를 더 안 찾아봐도 되는 글"이다.

### 11-1. 품질의 핵심 (없으면 쓰지 않는다)
1. **우리만 가진 예시**: 폼다 도구로 직접 채운 상황별 예시와 그 결과. 남의 글 예시를 옮기지 않는다.
2. **판단이 들어간 문장**: "이 상황이면 퇴직일을 이렇게 잡는 게 안전하다", "이 칸은 비워도 된다"처럼. 글마다 최소 2곳.
3. **사람들이 실제로 틀리는 지점**: 흔한 오해 1개 이상을 조문이나 숫자로 바로잡는다.
4. **확인한 사실만**(§7). 모르는 건 쓰지 않는다.

### 11-2. AI 티 나는 표현 (금지, check_post.py가 일부 검사)
- 상투어: "안녕하세요", "~에 대해 알아보겠습니다", "정리해 보겠습니다", "지금부터", "이번 글에서는", "마무리하며", "도움이 되셨길", "참고하시기 바랍니다", "궁금하셨던 분들"
- 빈 강조: "중요합니다", "필수적", "꼭 알아두세요", "핵심은 이겁니다", "답은 간단합니다", "결론적으로", "요약하자면", "한마디로"
- 부풀린 수식어: "다양한", "효과적인", "꼼꼼히", "현명한", "체계적인", "완벽 정리", "총정리", "A to Z"
- "~하는 것이 좋습니다" 글 전체 2회 초과 금지.
- 기계적 대칭(같은 길이 문단, 3개짜리 목록 반복, 모든 항목이 "굵은 제목. 설명").
- em dash, 이모지 남발, 느낌표. 번역투("~에 있어서", "~를 통해", "~하는 데 있어").

### 11-3. 틀 반복 금지
매 편 작성 전에 `ledger.tsv` 직전 4편 구성을 보고 아래 중 **최소 3가지를 바꾼다.**
1. 도입: 결론 먼저 / 실제 상황 장면 / 흔한 오해 반박 / 질문 하나 / 제도 변경 소식. 직전 2편과 같은 방식 금지.
2. 구성: 표 먼저 / 설명 먼저 / 예시 하나를 끝까지 따라가기 / 상황별 비교 / 질문-답 여러 개.
3. 소제목 개수(3~6)와 이름.
4. 표 개수(0~3)와 위치.
5. 끝맺음: 체크리스트 / 한 문장 판단 / 다음 서류 안내 / 없음.
6. 분량: 직전 4편 중 3편 이상과 ±15% 안이면 안 된다.
같은 도구를 여러 번 쓸 때(알바 이력서 t2·t17) 같은 문장 골격에 예시만 바꾼 글은 "대규모 콘텐츠 남용"이다.

### 11-4. 쓰는 방법
1. 그 검색어로 들어온 사람의 **진짜 질문 1개**를 한 문장으로 적는다(예: "다음 달 말에 그만두려는데 사직서 퇴직일 칸에 언제를 써야 하나").
2. 그 질문에 필요한 예시를 도구로 직접 채워 보고, 조문을 확인한 뒤 구성을 정한다.
3. 다 쓰고 소리 내 읽듯 다시 읽고, 사람이 안 할 말과 같은 말 반복을 지운다.

### 11-6. 제이퍼 문체 검증에서 나온 반복(폼다도 처음부터 피할 것)
- "숫자로 시작 → 둘째 문장 반전" 도입이 몰렸다. 질문·장면·판단 먼저를 섞는다.
- 첫 소제목 = 표 섹션이 몰렸다. 표를 중간·끝에 두거나 표 없는 글을 넣는다.
- 캡처 설명·도구 링크 문장·글쓴이 단락이 틀로 굳기 쉽다. 글마다 다르게.
- 어휘: "~수 있어요" 한 편 3회 이하, "결과적으로/~뜻이에요/~구조입니다/~셈이에요" 피함, "헷갈리면 ~만 기억하면" 정리 문장 금지.
- 경험을 지어내지 않는다("문의를 많이 받았다" 같은 문장 금지). 폼다 이용자 수·후기 숫자를 지어내지 않는다.

### 11-7. 폼다 t6~t10 문체 검증에서 나온 것 (11/23, 다음 묶음부터 피할 것)
